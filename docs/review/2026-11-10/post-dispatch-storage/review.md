execution journal after an accepted opening/closing acknowledgement. Position
accounting recreated an empty namespace before completion rejected its missing
scope. The original retained database still contained UNKNOWN; the replacement
contained no corresponding obligation. Independent enrollment already rejected
the following opening in both cases. This was not proof of a second native trade.
The [evidence](evidence.json) binds the original source phase and raw result.

closing preparation, closing inventory and closing completion. Position-store
methods propagate that flag into the existing paired transaction. Opening
completion already uses noncreating access. Generic setup/paper defaults remain;
an accepted acknowledgement is never storage-provisioning authority.

Seven regressions cover loss after dispatch, inside accounting, before
completion and before closing preparation. No replacement file appears. When
accounting already committed, its actual receipt remains in the JSON pair;
otherwise the pair is unchanged. The retained original still has UNKNOWN.
Stop and closing-lock reacquisition succeed after the tested failures. These
cases do not reconstruct a destroyed database or qualify all replacement races.
